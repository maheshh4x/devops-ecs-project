Technology Stack All tools and services used in this project
🐳

Docker

Containerizes the Flask app with all dependencies. Ensures the app runs the same everywhere — local, testing, or production cloud. Uses a multi-stage efficient Dockerfile.

📦

AWS ECR (Elastic Container Registry)

Private Docker image repository on AWS. Stores versioned Docker images securely. Acts as the "warehouse" for container images before deployment.

🎯

AWS ECS (Elastic Container Service)

Manages and runs Docker containers on AWS. Handles container lifecycle, health checks, and scaling. Runs containers across EC2 instances automatically.

⚖️

Application Load Balancer (ALB)

Distributes incoming user traffic across multiple ECS container instances. Provides health checks, high availability, and a single public endpoint URL.

⚙️

GitHub Actions (CI/CD)

Automated deployment pipeline. Triggered on every Git push to main branch. Automatically builds Docker image, pushes to ECR, and deploys to ECS — zero manual steps.

🐍

Python Flask + Gunicorn

Lightweight web application framework serving the frontend UI and REST API health endpoint. Gunicorn acts as the production WSGI server with multiple workers.

🔐

AWS IAM (Identity & Access Management)

Manages permissions and roles. The ECS Task Execution Role allows ECS to pull images from ECR and write logs to CloudWatch securely.

📊

AWS CloudWatch

Collects and monitors container logs in real-time. Provides metrics for CPU/memory usage. Enables debugging and performance monitoring of running containers.

How It Works — Step by Step The complete deployment flow from code to cloud
1

Developer Writes & Pushes Code

Developer writes Python Flask code locally and runs git push origin main to upload changes to GitHub repository.

2

GitHub Actions Pipeline Triggers Automatically

GitHub detects the push event and automatically starts the CI/CD pipeline defined in .github/workflows/deploy.yml. No manual action needed.

3

Docker Image is Built

GitHub Actions runner builds a Docker image from the Dockerfile. This packages the Flask app + Python + all dependencies into a single portable container image.

4

Docker Image Pushed to AWS ECR

The built Docker image is tagged and pushed to AWS Elastic Container Registry (ECR) — a private, secure image repository in the cloud. Both latest and commit-specific tags are stored.

5

ECS Task Definition Updated

The ECS Task Definition JSON is updated with the new Docker image URI. This tells ECS exactly which container image version to run, with resource allocation (CPU: 256, Memory: 512MB).

6

ECS Service Deploys New Containers

AWS ECS receives the updated task definition and performs a rolling deployment — starts new containers with the updated image, passes health checks, then terminates old containers. Zero downtime!

7

Load Balancer Routes User Traffic

The Application Load Balancer (ALB) distributes incoming user requests across multiple healthy ECS container instances. Health checks run every 30 seconds on the /health endpoint.

8

Users Access the Live App

Users open the public Load Balancer DNS URL in their browser and see the live Flask web application — deployed fully automatically through the CI/CD pipeline! ✅

⏱️

Total Deployment Time

From git push to live deployment on AWS ECS: approximately 3–5 minutes fully automated. No manual steps required after the initial setup.
